# Tutorial, mini-tutorials, actionable warnings, ES/EN — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a first-run guided tutorial with a first win, first-time mini-tutorials, actionable warnings with navigation, textbook links, and a full English locale to the live v2 game.

**Architecture:** Tutorial and mini-tutorial state live in the pure run layer (`js/sim/tutorial.js`, `js/sim/coach.js`) as JSON, with their own pause reasons and named highlight targets. Warnings carry a diagnosis and navigation actions computed in the sim (`js/sim/diagnose.js`). Copy and glossary are split per locale behind locale-aware lookups. The UI only renders highlights and buttons from those names.

**Tech Stack:** Same as v2: vanilla JS ES modules, Node `node --test`, GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-23-tutorial-i18n-design.md` (builds on `2026-11-23-rumbo-a-la-ipo-v2-design.md`).

## Global Constraints

- All v2 tests and the balance contract keep passing; no economics change (spec §2).
- `js/sim/*` stays pure (no DOM, no storage, no Math.random, no Date). Tutorial/coach state is plain JSON inside the run.
- Every student-facing string exists in both `es` and `en` with the same keys, placeholders and `[[term]]` markers (parity test).
- Tutorial and coach messages: ≤ 3 sentences each, one action at a time.
- The tutorial runs only when `createRun` receives `tutorial: true`. Ignoring it is allowed: time runs from step 3 on, and bankruptcy stays possible.
- Highlight targets are names (`data-tour="…"`), never DOM paths.
- CORE links: The Economy 2.0 microeconomics, `…/microeconomics/[es/]07-firm-and-customers-NN-<slug>.html`, slugs exactly as in spec §4.5.
- The tour explicitly presents the clock buttons, and step 3 highlights **Continuar** and says time only runs when you press it (the professor's own first-run confusion).

## Review Focus

1. **Reload in the middle of the tutorial** (each step, including mid-tour) → resumes at the same step with the same highlight and pause; nothing re-triggered. *(Task 3 round-trip test.)*
2. **A student who does the "wrong" thing during the tutorial**:
   - launches two products → the second is rejected with an explanation;
   - changes the price before step 5 → the tutorial still advances correctly;
   - answers the step-4 question wrong → still taught and can fix.
   *(Task 3 tests.)*
3. **Switching language mid-run** → every visible string, past chat messages included, re-renders. A missing English key never shows `⟦…⟧`. *(Task 8 parity test + Task 9 check.)*
4. **Mini-tutorials piling up in the same month** (rival + shock + valuation together) → queued one at a time and each shown once per student, also across runs. *(Task 4 tests.)*
5. **Replay tutorial after a finished run** → the next run has the tutorial; seen mini-tutorials stay seen. *(Task 7 check.)*

### Task 3: First-run tutorial in the sim

**Files:** Create `js/sim/tutorial.js` · Modify `js/sim/run.js`, `js/sim/world.js` (option), `js/sim/actions.js` (no change expected) · Test `tests/tutorial.test.js` (+ a `tutorialBot` in `tests/support/bots.js`)

**Interfaces — Produces:**
- `makeWorld(seed, line, { tutorial })`: when `tutorial` is true, wildcards scheduled before month 6 are shifted to ≥ 6, keeping order and ≥ 3 months of spacing.
- `createRun({ seed, line, meta, tutorial = false, coachSeen = [] })`. `run.tutorial = null | { step, tour, uid, devLoss, diagnose: { month, profit, optimal, optProfit }, done }` with `step ∈ 'tour' | 'launch' | 'develop' | 'diagnose' | 'fix' | 'verify' | 'done'`.
- `TOUR = ['cash', 'valuation', 'clock', 'tabs', 'chat', 'info']`: tour targets, one message each. `clock` presents Continuar/Pausa/1×/2×.
- `tutorialNext(run) → Run` advances the tour (the "Siguiente / Next" button). `tutorialSkipFix(run)` lets time run without fixing (explicit "Continuar de todos modos").
- `pauseReasons(run)` adds `'tutorial'` while the step is `tour`, `launch`, `diagnose` (until answered) or `fix` (until the price is set or skipped). `step()` is a no-op while `'tutorial'` is present.
- `tutorialHighlight(run) → string | null`: `tour` → current tour target; `launch` → `'launch'`; `develop` → `'clock-play'`; `diagnose` → `'demand-chart'`; `fix` → `'price:<uid>'`.
- Run messages (inbox type `tutorial`, `data: { id, vars, nav? }`), with ids:
  - `tut.tour.<target>`, `tut.launch`, `tut.secondLaunch`, `tut.develop`;
  - `tut.diagnose` (vars: devLoss, profit, optProfit);
  - `tut.fix` (vars: optimal), `tut.win` (vars: before, after), `tut.noWin`;
  - nav = `{ tab, target }`.
- Transitions:
  - `launch` → `develop`: on the first successful launch. During `launch`/`develop`, a second launch is rejected (`act.tutorialOneProduct`).
  - `develop` → `diagnose`: at the first month with Q > 0 for the tutorial product.
    - Time freezes.
    - Record `profit`, `optimal = (a + c)/2` for the current demand, and `optProfit` computed from it.
    - Trigger the `precio_optimo` question for that product, so the first launch's normal question is suppressed.
  - `diagnose` → `fix`: when that question is answered.
  - `fix` → `verify`: when the product's price is within ±5% of `optimal`, or via skip.
  - `verify` → `done`: next month. Emit `tut.win` if profit > diagnose profit, else `tut.noWin`.
- Mini-tutorials (Task 4) are held until `done`.

- [ ] **Step 1: Failing tests** (all with `tutorial: true`):
  - the step sequence for a `tutorialBot` that follows every instruction;
  - `pauseReasons` contains `'tutorial'` exactly in the frozen steps;
  - a second launch is rejected with `act.tutorialOneProduct`;
  - **first win:** for 40 seeds × both lines, the `tutorialBot` ends with `tut.win`, and the profit after the fix exceeds the diagnose profit;
  - an ignoring bot (never fixes; skips) can keep playing, and the run can still end in bankruptcy for at least one seed with a below-cost bot;
  - JSON round-trip at every step continues identically (Review Focus #1);
  - the wildcard shift: no wildcard before month 6 and ≥ 3 months of spacing;
  - `tutorial: false` → `run.tutorial === null`, with v2 behavior unchanged (whole v2 suite green).
- [ ] **Step 2–4:** FAIL → implement → PASS. **Step 5:** Commit `feat(sim): first-run tutorial`.

### Task 5: Actionable warnings

**Files:** Create `js/sim/diagnose.js` · Modify `js/sim/run.js` · Test `tests/diagnose.test.js`

**Interfaces — Produces:** `diagnose(run) → { culprit: 'belowCost'|'adsOverMargin'|'losingProduct'|'investing'|'fixedCosts', uid?, nav: [{ tab, target }] }`. The checks run in that order on the last month:
- **belowCost:** a product with P < c.
- **adsOverMargin:** a product's ad > its contribution.
- **losingProduct:** contribution − overhead − ad < 0.
- **investing:** a product still in development.
- **fixedCosts:** the fallback.

Message data changes:
- `runway` and `belowCost` get `culprit`, `uid`, `nav`.
- `crisisResolved` (not survived) gets `nav` per crisis id: costs → `tab:costos`, demand/rival/regulator → `tab:mercado`.
- `fine` and `investigation` get `months left` and `markup` vs. threshold.
- `rejected` gets fix vars: needed, have, and `monthsOfProfit` when profit > 0.

- [ ] **Step 1: Failing tests**:
  - each culprit is detected on a crafted state, in the right order;
  - a runway message carries `nav` and `culprit`;
  - a rejected launch carries `needed` and `have`.
- [ ] **Step 2–4:** FAIL → implement → PASS. **Step 5:** Commit `feat(sim): actionable warnings`.
